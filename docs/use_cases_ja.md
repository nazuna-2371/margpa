# 応用可能性 / Use Cases

---

## 1. 本資料の位置づけ

本資料は、MARGD（ARGD / DAGD）を複数のAI利用領域に応用した場合に想定される挙動変化と応用可能性を整理するための入口文書である。

ここで扱う内容は、実運用上の効果、安全性、正確性、専門判断の妥当性を保証するものではない。

本資料および配下の各文書は、MARGDをAI / LLMの実行時指示として適用した場合に、

どのような応答構造、前提保持、根拠分離、自己監査、修復、状態報告が期待され得るかを整理するための技術検討資料である。

MARGD / ARGD / DAGD の全体像は `docs/overview_ja.md`、ARGD / DAGD の技術概要は `docs/argd_and_dagd_ja.md`、

利用原則と限界は `docs/usage_and_limitations_ja.md` を参照する。

また、小規模検証と長大対話ログで観察された挙動については、`docs/validation_and_operation_observation_ja.md` を参照する。

## 3. 応用可能性として扱う理由

MARGDは、特定ドメイン専用の知識ベースではない。

MARGDの中心は、AI / LLMの実行時挙動に対して、次のような統治を与えることである。

```text
- 入力構造の保持
- 文脈・前提の保持
- 対象範囲の明示
- 情報不足の明示
- 事実、推論、仮定、評価の分離
- 複数論点の保持
- 利用者仮説への過度な追従の抑制
- 自己監査
- 修復
- 再固定
- 状態報告
```

これらは、医療補助AI、教育AI、Agentic AIのように、長い文脈、複数の前提、専門判断との境界、利用者の不安や誘導、外部操作リスクが関係する領域で特に重要になり得る。

そのため、本リポジトリでは、MARGDの応用可能性を、単なる例示ではなく、AIランタイム挙動の統治対象を確認するための技術検討として整理している。

## 4. 各応用例の概要

### 4.1 医療補助AI

医療補助AIの応用例では、MARGDを診断AIとしてではなく、受診前後の情報整理、問診補助、医療者への伝達補助に用いる場合を扱う。

主な観点は次の通りである。

```text
- 症状、生活背景、服薬、既往歴などの整理
- 確認済み情報と未確認情報の分離
- 医師に相談する検査候補の整理
- 診断断定の抑制
- 緊急性に関わる可能性のある兆候の分離
- 医師向け伝達メモへの変換
```

この応用例では、AIが医師の判断を代替するのではなく、利用者と医療者の間にある情報整理レイヤーとして機能する可能性を扱う。

詳細は `docs/use_cases/medical_assistive_ai_ja.md` を参照する。

---

### 4.2 教育AI・学習支援AI

教育AIの応用例では、MARGDを成績評価や課題代行のためではなく、学習者の理解過程を支援するために用いる場合を扱う。

主な観点は次の通りである。

```text
- 学習目的の保持
- 理解度・既習範囲の整理
- 誤答や誤解の原因分解
- 正答提示と学習支援の分離
- 課題代行に近い出力の抑制
- 段階的ヒント、復習リスト、質問整理への変換
```

この応用例では、AIが学習者の作業を肩代わりするのではなく、理解の現在地、誤解、前提不足、次の学習行動を整理する支援レイヤーとして機能する可能性を扱う。

詳細は `docs/use_cases/education_ai_ja.md` を参照する。

---

### 4.3 Agentic AI

Agentic AIの応用例では、MARGDを、目的達成のために計画、判断、ツール使用、外部操作、複数ステップ実行を行うAIに適用する場合を扱う。

主な観点は次の通りである。

```text
- 目的、制約、対象範囲の保持
- 権限境界の明示
- 実行前確認の安定化
- ツール使用条件の整理
- 取り消し困難な操作の抑制
- 失敗時の停止、修復、再固定
- 実行状態、未完了項目、残余リスクの報告
```

この応用例では、AIの自律実行を無制限に強めるのではなく、目的、制約、権限、確認、修復、監査を扱いやすくするための統治仕様としてMARGDを検討する。

詳細は `docs/use_cases/agentic_ai_ja.md` を参照する。

---

### 4.4 共通挙動パターン

共通挙動パターンでは、医療補助AI、教育AI、Agentic AIの3例を横断し、MARGD適用時に共通して想定される挙動を整理する。

主な観点は次の通りである。

```text
- 文脈・前提の保持
- スコープ管理
- 不確実性の明示
- 複数論点・複数解釈の保持
- 利用者仮説への過度な追従の抑制
- 出力形式の構造化
- 失敗時の修復
- 状態報告・監査可能性
```

この文書は、個別ドメインの詳細ではなく、MARGDが複数領域を横断して扱い得るAIランタイム挙動の共通構造を示すための文書である。

詳細は `docs/use_cases/common_behavior_patterns_ja.md` を参照する。

## 5. 応用可能性を読む際の注意

本リポジトリの応用例は、MARGDが各領域で効果を保証することを示すものではない。

特に、次の点に注意する必要がある。

```text
- 医療、教育、法務、金融、セキュリティなどの専門判断を代替しない
- モデル自体の知識、推論能力、長文保持能力を直接変更しない
- 入力情報が誤っている場合、その誤りを自動的に保証・訂正するものではない
- 外部ツール側の権限管理、監査ログ、ロールバック機構、アクセス制御を代替しない
- 実運用には、専門家レビュー、リスク評価、人間監督、外部安全機構との併用が必要である
```

MARGDは、AIが常に正しい判断をすることを保証するものではない。

MARGDは、AI / LLM の応答を、前提保持、根拠分離、不確実性開示、自己監査、修復、再固定、状態報告が行われやすい構造へ寄せるための外部統治層として扱うのが妥当である。

## 6. 応用例と検証文書の関係

本資料の応用例は、仮説的な技術検討である。

一方で、`docs/validation_and_operation_observation_ja.md` では、MARGDを適用した小規模検証と長大対話ログにおいて、

応答構造、前提保持、根拠分離、自己監査、修復、状態報告に関する挙動が一部観察されたことを整理している。

したがって、本リポジトリでは次のように文書を分けている。

| 文書                                                | 役割                      |
| ------------------------------------------------- | ----------------------- |
| `docs/use_cases_ja.md`                            | 応用可能性の入口                |
| `docs/use_cases/` 配下                              | 個別応用例の詳細                |
| `docs/validation_and_operation_observation_ja.md` | 小規模検証と長大対話ログで観察された挙動の整理 |

この分離により、応用可能性と観察結果を混同しないようにしている。

## 7. 今後の応用拡張候補

今後、MARGDの応用可能性は、次のような領域にも拡張できる可能性がある。

```text
- 法務補助AI
- 金融補助AI
- セキュリティ支援AI
- 研究補助AI
- ソフトウェア開発支援AI
- カスタマーサポートAI
- 組織内ナレッジ管理AI
- AI監査支援
- 長期プロジェクト支援
```

ただし、これらは現時点では検討候補であり、各領域で実運用上の妥当性を主張するには、領域別の評価設計、比較可能な入力データ、実行ログ、失敗例、専門家レビュー、リスク評価が必要である。

## 8. 暫定まとめ

MARGDは、特定ドメインの専門知識や安全性を保証する仕組みではない。

一方で、複数のAI利用領域に共通する次の処理に対して、外部指示層から統治を与える枠組みとして応用可能性がある。

```text
- 文脈保持
- 前提固定
- スコープ管理
- 情報不足の明示
- 複数論点の保持
- 利用者仮説への過度な追従の抑制
- 出力形式の構造化
- 失敗時の修復
- 再固定
- 状態報告
- 監査可能性の向上
```

そのため、本資料では、MARGDを個別ドメイン専用の解決策ではなく、AI / LLM のランタイム挙動を整理・制御するための統治仕様として位置づけ、その応用可能性を整理している。
