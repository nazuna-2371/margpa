# Appendix: ハルシネーション観点から見たMARGD

---

## 1. 本資料の位置づけ

本資料は、MARGD の小規模検証および本リポジトリ公開用Docsの設計・検証・再整理を行った長大対話ログを、ハルシネーションという観点に絞って考察する補足文書である。

本資料では、ハルシネーションを狭義の「存在しない事実の生成」だけに限定しない。

MARGD の文脈では、より広く、次のような挙動もハルシネーション関連リスクとして扱う。

```text
- 存在しない事実を述べる
- 根拠がないのに断定する
- 情報不足下で確信的に言う
- 推論を事実のように扱う
- 未確認情報を確認済み情報として扱う
- 根拠があるように見える説明を後付けする
- 参照資料にないことを、参照資料由来のように述べる
- 前回回答の問題点を再評価せず、自己正当化する
````

本資料は、MARGD がハルシネーションを完全に防ぐと主張するものではない。

目的は、MARGD がハルシネーション関連リスクをどのように扱おうとしているか、また小規模検証と長大対話ログから何が観察されたかを整理することである。

## 2. MARGDにおけるハルシネーションの扱い

MARGDでは、ハルシネーションは単独の失敗ではなく、複数の関連失敗と接続して扱われる。

代表的には、次のようなものが関係する。

| 分類                                             | 内容               |
| ---------------------------------------------- | ---------------- |
| hallucination                                  | 存在しない事実や根拠を生成する  |
| unsupported assertion                          | 根拠不足のまま主張する      |
| false certainty under insufficient information | 情報不足下で確信的に述べる    |
| confidence without basis                       | 確信度の根拠を示さない      |
| evidence basis omission                        | 重要主張に根拠を付けない     |
| traceability omission                          | 根拠の追跡限界を示さない     |
| fact inference confusion                       | 事実、推論、仮定、評価を混同する |
| premise drift                                  | 既存前提をずらして扱う      |
| unsupported source-like attribution            | 根拠がないのに出典風の扱いをする |

このため、MARGDにおけるハルシネーション対策は、単に「嘘をつくな」と命じるものではない。

むしろ、次のような分解を通じて、ハルシネーションが発生しにくい応答構造へ寄せることを狙う。

```text
- 何が確認済みか
- 何が未確認か
- 何が推論か
- 何が仮定か
- 何が評価か
- どの主張に根拠があるか
- どの主張は根拠不足か
- どこから先は判断不能か
```

## 3. 3ターン小規模検証で見えたハルシネーション関連リスク

3ターン小規模検証では、典型的な「完全に存在しない事実の生成」だけでなく、より実務的なハルシネーション関連リスクが観察対象になった。

特に重要だったのは、次の4種類である。

| 種類       | 内容                       | 例                     |
| -------- | ------------------------ | --------------------- |
| 情報不足下の断定 | 規程本文や入力全文がないのに、結論を強める    | 「問題ない可能性が高い」「漏洩はなかった」 |
| 推論と事実の混同 | 推測できることを、確認済みのように扱う      | 「利用した可能性」を「利用した」と扱う   |
| 未確認情報の脱落 | 結論に必要な未確認事項を省く           | ツール名、入力全文、承認有無を軽視する   |
| 後付け正当化   | 根拠確認後に、前回回答を十分に再評価せず維持する | 断定しすぎた表現を弱めない         |

これらは、狭義のハルシネーションよりも地味である。

しかし、業務、監査、規程確認、RAG、社内ナレッジ、Agentic AI では、むしろこの種のリスクの方が実害に近い場合がある。

## 4. 3ターン小規模検証で観察された抑制方向

MARGDあり条件では、次のようなハルシネーション抑制に近い挙動が一部で観察された。

| 観点        | 観察された挙動                        |
| --------- | ------------------------------ |
| 確認済み情報の分離 | 報告メモに書かれていることだけを確認済み情報として扱う    |
| 未確認情報の保持  | 利用日時、入力全文、ツール名、承認有無などを未確認として残す |
| 推論の明示     | 顧客名を伏せても安全とは限らない、などを推論として扱う    |
| 断定抑制      | 「確認されていない」と「なかった」を分ける          |
| 自己監査      | 前回回答に断定しすぎや未確認事項の脱落がないか点検する    |
| 修正方針      | 本来どう答えるべきだったかを示す               |

特に監査文書系の検証では、「情報漏洩は確認されていない」と「情報漏洩はなかった」を分けることが重要だった。

これは、ハルシネーションを「架空事実の生成」としてだけでなく、「調査未了を事実確定のように扱う誤り」として見る必要があることを示している。

## 5. MARGDなし条件でも慎重な応答はあった

本検証では、MARGDなし条件でも、一定以上慎重な応答を示すモデルがあった。

そのため、次のような単純化は避ける必要がある。

```text
避けるべき解釈：
MARGDなし = ハルシネーションする
MARGDあり = ハルシネーションしない
```

より正確には、次のように扱う。

```text
MARGDなし条件でも、モデル自身の安全層、指示追従性、慎重性により、十分に抑制された応答が出る場合がある。

一方で、MARGDあり条件では、根拠分離、未確認情報保持、自己監査、修復方針がより明示される場合があった。
```

つまり、MARGDはハルシネーションを完全に防ぐ装置ではない。

MARGDは、ハルシネーション関連リスクを検出・抑制・修復しやすい応答構造へ寄せるための runtime governance specification として扱うのが妥当である。

## 6. 長大対話ログで見えたハルシネーション関連リスク

本資料作成過程の長大対話ログでは、短い3ターン検証とは別種のリスクが見えた。

長い対話では、明確な架空事実の生成だけでなく、次のような形でハルシネーション関連リスクが発生し得る。

| リスク      | 内容                              |
| -------- | ------------------------------- |
| 前提の薄化    | 以前に固定した方針や除外事項が弱まる              |
| 文書役割の混線  | 概要書、技術概要、利用原則、検証文書の役割が混ざる       |
| 過去方針の再提案 | 既に除外したテーマや案が再び出てくる              |
| 表現固定の崩れ  | 「状態報告はDAGDに組み込まれた機能」などの固定表現が弱まる |
| 推論の実測化   | 反実仮想や推測を、実測結果のように扱う             |
| 一般論への回帰  | MARGD固有の話が、一般的なプロンプト論へ薄まる       |
| 自己正当化    | 前回出力のズレを、十分に再評価せず言い換えで済ませる      |

この種のズレは、狭義のハルシネーションとは呼ばれにくい。

しかし、長大な研究・設計対話では、前提が崩れたまま自然な文章が生成されるため、結果として「もっともらしいが、実際の文脈から外れた出力」になり得る。

MARGDが扱おうとしているのは、このような長大文脈上のハルシネーション関連リスクでもある。

## 7. ハルシネーションとドリフトの関係

短い応答では、ハルシネーションは「事実の誤り」として見えやすい。

一方で、長大対話では、ハルシネーションはドリフトと結びつきやすい。

| 短期応答での形     | 長大対話での形               |
| ----------- | --------------------- |
| 存在しない事実を述べる | 前提が薄れ、別の前提で話を進める      |
| 根拠なく断定する    | 以前の決定事項を無視して新しい結論を作る  |
| 推論を事実化する    | 反実仮想を実測として扱う          |
| 不確実性を隠す     | 未検証領域を検証済みに近い表現で扱う    |
| 出典を捏造する     | 過去ログにない合意を、あったかのように扱う |

このため、長大対話におけるハルシネーション対策は、単に「正しい知識を出す」ことでは足りない。

次のような統治が必要になる。

```text
- 前提保持
- 決定事項保持
- 変更点と未変更点の分離
- 実測と推論の分離
- 未検証領域の明示
- ドリフト検出
- 修復
- 再固定
```

これらは、MARGDが主に扱おうとしている領域である。

## 8. 本資料作成過程の長大対話ログで観察された自己修復

本資料作成過程の長大対話ログでは、ハルシネーション関連リスクに近いズレが発生し、その後に修復された場面があった。

代表的には、次のようなものがある。

| ズレ                       | 修復内容                                   |
| ------------------------ | -------------------------------------- |
| 状態報告を「過剰ガバナンス」として弱く見せすぎた | 状態報告はDAGDに組み込まれた機能であり、課題は表示制御であると再固定した |
| 3ターン検証の限界を効果不足側へ寄せた      | 効果不足ではなく、検証対象がMARGDの主武器より短すぎると再定義した    |
| MARGD側課題とモデル依存制約を混同した    | 調整可能な課題と、モデル側で吸収しきれない制約を分離した           |
| 効きやすいモデルの条件を狭く一般化した      | 大手モデルでも長大化・複雑化すればMARGDが効く可能性を再固定した     |
| 公開文書向け表現が英語混じりになりすぎた     | 用語以外は日本語で書く方針を再固定した                    |

これらは、架空事実の生成ではない。

しかし、文脈、前提、目的、表現方針からの逸脱であり、長大対話においては実質的にハルシネーション関連リスクとして扱う価値がある。

## 9. MARGDがハルシネーションを抑える可能性がある経路

MARGDがハルシネーション関連リスクを抑える可能性がある経路は、主に次の通りである。

| 経路     | 内容                          |
| ------ | --------------------------- |
| 前提保持   | 以前に固定した条件を保持し、勝手な前提変更を抑える   |
| 根拠分離   | 直接根拠、推論、仮定、評価を分ける           |
| 不確実性開示 | 情報不足時に、判断不能な範囲を明示する         |
| 非迎合    | ユーザーの断定要求にそのまま従わない          |
| 反証     | 結論の弱点や破綻条件を確認する             |
| 自己監査   | 前回回答の断定、根拠不足、未確認情報扱いを点検する   |
| 修復     | unsupported な主張を撤回、修正、再限定する |
| 再固定    | 修正後の前提や方針を改めて固定する           |
| 状態報告   | 現在の統治状態、修復状態、未解決事項を可視化する    |

このうち、特に長大対話で重要なのは、前提保持、自己監査、修復、再固定である。

短期応答では見えにくいが、対話が長くなるほど、これらの有無が出力の安定性に影響しやすくなる。

## 10. MARGDでもハルシネーションを完全には防げない理由

MARGDは、ハルシネーションを完全に防ぐものではない。

理由は次の通りである。

```text
- モデル重みや学習データを変更するものではない
- 組み込み安全層を上書きするものではない
- モデルの知識不足を補完するものではない
- モデルの長文保持能力を根本的に拡張するものではない
- 入力情報が誤っている場合、その誤りを自動的に検出できるとは限らない
- モデルがMARGDを十分に保持・適用できない場合がある
- 自己監査が表面的になる場合がある
- 状態報告の粒度や頻度がモデルごとに揺れる
```

また、MARGDがあることで出力が構造化されても、その構造自体が正しいとは限らない。

表形式で整理されていても、根拠が誤っていれば、整った形の誤りになる可能性がある。

したがって、MARGDはハルシネーション対策の一部にはなり得るが、完全な防止策ではない。

## 11. ハルシネーション対策としてのMARGDの位置づけ

MARGDは、ハルシネーションを直接消す魔法ではない。

より正確には、MARGDはハルシネーション関連リスクを次のように扱うための外部統治層である。

```text
- 発生しにくい応答構造へ寄せる
- 発生した場合に検出しやすくする
- 検出後に修復しやすくする
- 修復後に前提を再固定しやすくする
- どこが不確実かを見えるようにする
```

この意味で、MARGDは「ハルシネーション防止プロンプト」というより、ハルシネーション関連リスクを管理するための runtime governance foundation として位置づけるのが妥当である。

## 12. 3ターン検証から言えること

3ターン小規模検証から言えることは限定的である。

言えることは次の通りである。

```text
- MARGDあり条件では、根拠不足下の断定抑制が一部観察された
- MARGDあり条件では、確認済み情報、未確認情報、推論の分離が一部観察された
- MARGDあり条件では、自己監査により前回回答の問題点を点検する出力が一部観察された
- MARGDなし条件でも、慎重な応答を行うモデルはあった
- 3ターン検証だけでは、長大対話におけるハルシネーション抑制効果は評価できない
```

---

## 13. 長大対話ログから言えること

本資料作成過程の長大対話ログから言えることも、単一事例に限られる。

言えることは次の通りである。

```text
- MARGDあり状態で、前提の再固定、自己監査、修復、状態報告が観察された
- 文脈上のズレを検出し、修正内容と再固定内容を明示する場面があった
- 状態報告により、現在の統治状態や修復状態を可視化できた
- ただし、同条件でのMARGDなし長大対話ログは取得していない
- そのため、MARGDなしの場合との厳密比較はできない
```

この観察は、MARGDが長大対話でハルシネーション関連リスクを管理する可能性を示す補助材料である。

ただし、比較検証ではなく、MARGDあり状態での単一運用観察である。

## 14. 今後の検証課題

ハルシネーション観点で今後検証すべき課題は次の通りである。

| 検証課題          | 内容                                  |
| ------------- | ----------------------------------- |
| 長大対話での未使用状態比較 | 同等条件で、MARGDあり / なしの長大対話ログを比較する      |
| 反実仮想の実測化      | なし条件で本当にどのようなドリフトや断定が起きるか確認する       |
| 根拠資料付きRAG検証   | 参照資料にない主張が混入するかを見る                  |
| 複数文書検証        | 文書間で根拠、推論、前提が混ざるかを見る                |
| 自己監査の深さ検証     | 前回回答の問題点を表面的に列挙するだけか、実質的に修復するかを見る   |
| 状態報告の検証       | ハルシネーション関連リスクを状態報告でどこまで検出・表示できるかを見る |
| ユーザー介入差       | ユーザーが再固定や修正指示を出す場合と出さない場合の差を見る      |
| 専門ドメイン検証      | 医療補助、教育、法務、監査、Agentic AI での挙動を見る    |

## 15. 暫定結論

MARGDは、ハルシネーションを完全に防ぐ仕組みではない。

しかし、MARGDは、ハルシネーション関連リスクを単なる「事実誤り」としてではなく、

根拠不足、情報不足下の断定、推論と事実の混同、前提ドリフト、自己修復不足として扱う。

3ターン小規模検証では、MARGDあり条件において、根拠分離、断定抑制、未確認情報保持、自己監査、修復方針の提示が一部で観察された。

本資料作成過程の長大対話ログでは、MARGDあり状態で、前提の再固定、自己監査、修復、状態報告が観察された。

ただし、いずれもハルシネーション抑制効果を包括的に実証するものではない。

本資料の範囲では、MARGDはハルシネーションを消すものではなく、ハルシネーション関連リスクを構造的に扱い、

検出・修復・再固定しやすくするための runtime governance foundation として位置づけるのが妥当である。
