# Quickstart

---

## 1. 本資料の目的

本資料は、MARGD を実際に使い始めるための最小手順を示す文書です。

MARGD / ARGD / DAGD の詳しい説明は、以下を参照してください。

```text
docs/overview_ja.md
docs/argd_and_dagd_ja.md
docs/usage_and_limitations_ja.md
```

本資料では、主に次を扱います。

```text
- どの定義ファイルを使うか
- 最初にどう投入するか
- スレッドの目的をどう固定するか
- 挙動が不安定になった場合にどう再固定するか
- 長いスレッドでARGD / DAGDが薄まった場合にどう再投入するか
```

---

## 2. 注意事項

本手順は、MARGD を試すための最小手順です。
動作を保証するものではありません。

LLM、UI、モード、ファイル投入方法、スレッド長、モデル性能により挙動は変わる場合があります。

可能な限り、推論強化・思考拡張・高性能推論向けのモードを使用することを推奨します。
ARGD / DAGD は、モデルの推論力、長文保持力、指示追従力が高いほど真価を発揮しやすいためです。

詳細な利用原則と限界は `docs/usage_and_limitations_ja.md` を参照してください。

---

## 3. 推奨ファイル

初めて使う場合は、結合版JSONを推奨します。

基本推奨は次のファイルです。

```text
definitions/argd_v0.3.0_en_dagd_v0.4.4_en.json
```

反証、非迎合、弱点指摘、精密レビューをより重視する場合は、次のファイルを使用できます。

```text
definitions/argd_v0.3.1_en_dagd_v0.4.4_en.json
```

日本語定義を使いたい場合は、次のファイルを使用できます。

```text
definitions/argd_v0.3.0_ja_dagd_v0.4.4_ja.json
definitions/argd_v0.3.1_ja_dagd_v0.4.4_ja.json
```

部品単位で使いたい場合は、`definitions/` 配下の ARGD / DAGD 個別JSONを使用してください。

```text
definitions/argd_v0.3.0_en.json
definitions/argd_v0.3.0_ja.json
definitions/argd_v0.3.1_en.json
definitions/argd_v0.3.1_ja.json
definitions/dagd_v0.4.4_en.json
definitions/dagd_v0.4.4_ja.json
```

---

## 4. ARGD v0.3.0 と ARGD v0.3.1 の違い

基本的には、ARGD v0.3.0 を推奨します。

ARGD v0.3.0 は、前提保持、文脈保持、根拠分離、情報不足時の断定抑制、修復を重視した基本版です。

ARGD v0.3.1 は、反証、非迎合、弱点指摘、再検討をより強く含みます。

そのため、研究、設計、レビュー、精密検証には ARGD v0.3.1 が向く場合があります。
一方で、反証や指摘を重く感じる用途では、ARGD v0.3.0 の方が扱いやすい場合があります。

```text
通常用途:
argd_v0.3.0 + dagd_v0.4.4

反証・精密レビュー重視:
argd_v0.3.1 + dagd_v0.4.4
```

## 5. 最小手順

最小手順は次の通りです。

```text
1. 結合版JSONを投入する
2. ARGD / DAGD の反映を確認する
3. このスレッドの目的を設定する
4. 実作業を開始する
5. 必要に応じて、自己監査、即時修復、再固定を行う
6. 長いスレッドで薄まってきた場合は、ARGD / DAGD を再投入する
```

ARGD / DAGD は、個別に貼っても、結合したJSONファイルで投入しても構いません。

ただし、ファイル数制限や貼り付け認識の問題を避けるため、初回は結合版JSONを使う方法を推奨します。

---

## 6. 1ターン目：初期化

1ターン目では、ARGD / DAGD の定義ファイルを投入し、反映確認を行います。

たとえば、結合版JSONを添付または貼り付けたうえで、以下のいずれかを入力します。

```text
反映、復唱。もし一部反映あるいは反映不可の場合は、要因も説明。
```

```text
反映、復唱、簡潔に。
```

```text
反映。復唱は不要。反映実施済 / 未実施のみ報告。
```

復唱が長すぎる場合は、3つ目の形式を使うと軽量になります。

---

## 7. 2ターン目：このスレの目的設定

ARGD / DAGD の反映後、このスレッドの目的を設定します。

通常文で書く場合の例です。

```text
このスレの目的設定
ARGDとDAGDを用いた際の、Agentic AIの長所、短所を補完関係にさせるための研究、検討。
変更が必要な際はこちらから明示的発言を行う。
スレの目的を固定。
まずキミの見解を。
```

Markdown形式で書く場合の例です。

```markdown
# このスレの目的設定
- Agentic AIの長所、短所についての研究、検討。
- ARGDとDAGDを応用したケースを想定。
- 変更が必要な際はこちらから明示的発言を行う。
- スレの目的を固定。
- まずキミの見解を。
```

目的設定では、少なくとも次を明示すると安定しやすくなります。

```text
- このスレッドで何をしたいか
- どの範囲を扱うか
- 必要時に変更する可能性があるか
- 目的を固定するか
- まず何を出してほしいか
```

## 8. 3ターン目以降：実作業

目的設定後は、通常通り作業を進めます。

MARGD は、短い対話で劇的な差を出すためだけのものではありません。
特に、次のような作業で効果を観察しやすくなります。

```text
- 長文レビュー
- 仕様整理
- 研究・検討
- 前提が多い相談
- 複数文書をまたぐ整理
- 自己監査や修復が必要な作業
- 長大コンテキスト運用
```

---

## 9. 挙動不安定時

出力がズレた、前提が薄れた、修復が必要だと感じた場合は、以下のように入力します。

```text
自己監査、即時修復、再固定。
過去ログを参照し、自己観測上 / 推論上のスコアで構わないので、修復前後のスコアを図で並べて出力。
```

または、より短く次のように入力します。

```text
自己監査、即時修復、再固定。
```

これにより、過去ログ、現在の前提、ズレ、修復内容、再固定内容を整理しやすくなります。

ただし、モデルや環境によって、自己監査や修復の深さには差があります。

---

## 10. 長スレ化して ARGD / DAGD が薄まった場合

スレッドが長くなると、LLMの性質上、ARGD / DAGD の反映が薄まる場合があります。

その場合は、ARGD / DAGD の定義ファイルを再投入し、次のように入力します。

```text
添付ファイルを再確認 / 反映、状態自己検証 / 監査、再固定。
過去ログを参照し、自己観測上 / 推論上のスコアで構わないので、修復前後のスコアを図で並べて出力。
```

または、より短く次のように入力します。

```text
添付ファイルを再確認 / 反映、状態自己検証 / 監査、再固定。
```

これは、長大スレッドで前提、目的、制約、修復方針を再確認するための操作です。

一度投入すれば永続的に完全保持される、という前提では扱わないでください。

## 12. うまく動かない場合

うまく動かない場合は、次を確認してください。

```text
- 結合版JSONを使っているか
- ARGD / DAGD の両方が投入されているか
- 反映確認を行ったか
- スレッドの目的設定を行ったか
- 出力が長すぎる場合、復唱不要の初期化文を使ったか
- スレッドが長くなりすぎていないか
- 必要に応じて再投入したか
- 推論強化・思考拡張・高性能推論向けのモードを使っているか
```

軽量モデル、短文応答向けモデル、長文保持が弱いモデルでは、MARGD の保持、反映、自己監査、修復、再固定が不安定になる場合があります。

その場合は、より軽量な派生版を用意する、投入内容を短くする、作業範囲を分ける、再固定頻度を上げるなどの調整が必要です。

## 13. 向いている使い方

MARGD は、特に次のような用途に向きます。

```text
- 研究
- 設計
- 精密レビュー
- 長文Docs作成
- 前提が多い相談
- 複数ターンにまたがる検討
- 自己監査や修復が必要な作業
- 長大コンテキスト運用
```

一方で、軽い雑談、短い質問、即答が必要な軽量タスクでは、過剰に感じられる場合があります。

また、MARGDはあくまで基盤的な構文であるため、ドメイン特化版も含め、必要に応じて適宜カスタマイズを行なってください。

改変、翻訳、派生物の作成、再配布時の条件については、`LICENSE` および `NOTICE.md` を参照してください。

## 15. まとめ

最小運用では、次の流れを推奨します。

```text
1. 結合版JSONを投入する
2. 反映確認を行う
3. このスレの目的設定を行う
4. 作業を開始する
5. 不安定になったら自己監査、即時修復、再固定を行う
6. 長スレ化して薄まったら、ARGD / DAGD を再投入する
```

基本推奨は次です。

```text
definitions/argd_v0.3.0_en_dagd_v0.4.4_en.json
```

反証・精密レビュー重視の場合は次を使用できます。

```text
definitions/argd_v0.3.1_en_dagd_v0.4.4_en.json
```

MARGD は、LLMの基礎性能を置き換えるものではありません。
ただし、十分な性能を持つLLM環境では、前提保持、根拠分離、自己監査、修復、再固定、状態報告を支援する外部統治層として利用できる可能性があります。
